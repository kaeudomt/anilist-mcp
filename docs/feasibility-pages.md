# Historical GitHub Pages snapshot feasibility (superseded)

**Historical Pages proposal:** The repository is now public, but GitHub Pages remains disabled. Do not deploy this Pages design or publish its URLs.

Checked 2026-10-27. This note separates documented capabilities, local tests, and remaining account-side checks.

## Verified by documentation or local test

- [GitHub Pages publishes static files](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) and supports MIME types by file extension, including JSON. A GitHub Actions deployment artifact needs a top-level entry file, so this project generates `index.html` in addition to the three requested exports. Public Pages output is accessible on the internet even when the repository itself is private.
- [GitHub's recommended custom workflow](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) uploads a built artifact, then deploys it with `pages: write` and `id-token: write`. The workflow here has separate build and deploy jobs and uploads only `dist/`; an AniList or validation failure prevents a deployment.
- [AniList requires POST](https://docs.anilist.co/guide/graphql/) for GraphQL and allows public reads without OAuth. Its [list guide](https://docs.anilist.co/guide/graphql/queries/media-list) says to include custom lists when fetching all entries. The [pagination guide](https://docs.anilist.co/guide/graphql/pagination) says to rely on `hasNextPage`, not `total` or `lastPage`. The [Page limit](https://docs.anilist.co/reference/object/page) is 5,000 entries; this exporter fails clearly at that limit rather than publishing an incomplete file.
- AniList's [rate-limit guide](https://anilist.gitbook.io/anilist-apiv2-docs/docs/guide/rate-limiting) currently notes 30 requests/minute in a degraded state. The exporter spaces requests at least 2.1 seconds apart, retries transient HTTP failures and `429`, and honors `Retry-After`.
- A live, unauthenticated local run fetched **170 unique public entries** for `kaeudomt`, including **65 completed** and **3 currently watching**, and generated/validated all four files. At that run, `anime-list.json` was about **287 KB**, `summary.json` about **12.5 KB**, and `summary.md` about **4 KB**. These values are a snapshot, not permanent expectations.
- The account's reported score format was `POINT_10_DECIMAL`. AniList's [MediaList reference](https://docs.anilist.co/reference/object/medialist) says the `score(format:)` argument forces conversion; this project does not pass it, and stores the user score format alongside the values.

## Limits and unresolved checks

- GitHub Pages deployment and HTTPS access **cannot be tested for this repository before approval and publication**. [GitHub's site guide](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site) says publication can take up to 10 minutes. Its [Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits) include a 1 GB published-site limit and 10-minute deployment timeout; the measured files are far smaller.
- A successful HTTPS fetch does **not** prove regular ChatGPT Plus browsing will read all of a 287 KB JSON file. OpenAI documents [web search](https://learn.chatgpt.com/docs/web-search), but does not guarantee arbitrary JSON retrieval, complete text extraction, or a fresh uncached response for these URLs. The 4 KB `summary.md` and visible refresh timestamp are intended as the first browsing target. ChatGPT Plus must be tested after publication, in an ordinary **Chat** conversation.
- The URL remains stable while content changes every successful run. Pages delivery and ChatGPT web search may cache content; this project's timestamp lets a reader detect stale data, but cannot force a fresh ChatGPT fetch. The six-hour interval is a schedule, not a strict freshness guarantee.
- [GitHub scheduled workflows](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows) can be delayed or dropped under load, run only from the default branch, and are automatically disabled in a **public repository after 60 days without repository activity**. The cron time is 17 minutes past the hour to reduce load-related delays. A long-lived public repository may require occasional activity or re-enabling the schedule. This is a material maintenance limit of this hosting plan.
- AniList's [API terms](https://anilist.gitbook.io/anilist-apiv2-docs/docs/guide/terms-of-use) prohibit using the API as a backup/storage service and prohibit hoarding or mass collection. This design publishes one overwritten presentation snapshot of a single public account, with no archive of historical snapshots; treating that as acceptable personal analytics use is an **inference**, not an AniList approval. The generated public page identifies itself as unofficial and for AniList, following the terms' naming guidance.

## Post-deployment verification gate

1. Open each published URL in a private browser window; require HTTP 200, JSON parsing for both `.json` files, and matching UTC timestamps across all three exports. Confirm `summary.md` is readable as text.
2. Compare `total_entries`, status counts, and several titles/scores/progress values with the live AniList profile or a fresh direct API query. The workflow log should say how many entries were exported. Reject a deployment if counts disagree.
3. In a **regular ChatGPT Plus Chat**, give the direct `summary.md` URL and ask: “Open this exact URL, quote its UTC refresh timestamp, report the completed and currently watching counts, and cite the page.” Check that ChatGPT actually opens/cites that page and gives the published values. Then ask it to open `anime-list.json` and answer a lookup involving a title absent from `summary.md`. If it cannot, the complete-list ChatGPT success criterion remains unmet.
4. After the next scheduled run, repeat the timestamp test to assess freshness and caching. A current browser result with an older ChatGPT result indicates ChatGPT caching or retrieval limitations.
